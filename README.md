# HCI-Mobile-Timetable-Prototype

> 华东师范大学《人机交互技术》课程期末作业  
> 改进对象：华东师范大学移动端官方课表  
> 交付形态：移动端 Web 高保真交互原型

---

## 一、项目概述

### 我们要解决什么问题？

官方手机端课表存在以下痛点：
| 问题              | 具体表现                           |
| ----------------- | ---------------------------------- |
| 信息密度低        | 课程色块间距大，屏幕利用率低       |
| 颜色区分不足      | 不同课程撞色                       |
| 视觉层次弱        | 顶栏全白，缺少功能分区             |
| 缺乏“现在”感知    | 看不出当前节次、今日进度、下一节课 |
| 周次/课程信息分散 | 单双周、结课周等规则不直观         |

### 我们的方案

**降低「获取当前/下一节课信息」的认知负荷与交互步数。**

用户不必心算「现在第几节、还剩几节、下一节在哪」，系统主动呈现进度、高亮与快捷入口。

### 已实现功能

- [x] 紧凑课表网格 + 圆角色块
- [x] 按课程分色（用户提供配色 + 白字）
- [x] 深蓝顶栏「课程查询」+ 周次栏（与课表同宽、同色）
- [x] 周次切换（1–17 周）：点击「第 X 周」→ 纵向滑动列表；支持 ‹ › 与课表左右滑
- [x] 单双周 / 结课周过滤
- [x] 左侧节次 + 具体上课时间；第 5–6、10–11 节间用餐空行
- [x] 今日进度条（按节次计剩余数量）
- [x] 当前节次行/今日列高亮
- [x] 底部悬浮栏：进行中 / 下一节课
- [x] 点击课程块 → 详情页（课程名、代码、教师、时间、地点、人数、周数、备注）
- [x] 数据：`schedule.csv` 手动维护，学期写死“2026春”

## 二、本地运行

1. 用 VS Code 打开本项目文件夹  
2. 安装 **Live Server** 插件  
3. 右键 `index.html`，然后 **Go Live**  
4. 浏览器访问（勿直接双击 HTML，`file://` 无法加载 CSV）

```
HCI-Mobile-Timetable-Prototype/
├── index.html          # 课表主页
├── detail.html         # 课程详情
├── schedule.csv        # 课表数据
├── css/styles.css
└── js/
    ├── config.js       # 学期、节次时间、配色、网格行映射
    ├── schedule.js     # CSV 解析、周次规则、进度计算
    ├── app.js          # 主页逻辑
    └── detail.js       # 详情页逻辑
```

### 修改课表数据

编辑 `schedule.csv`，一行 = 网格上的一个课程块。保存后刷新页面即可。

| 列名                        | 说明                                        |
| --------------------------- | ------------------------------------------- |
| `courseCode`                | 课程代码                                    |
| `courseName`                | 课程名                                      |
| `teacher`                   | 教师                                        |
| `dayOfWeek`                 | 1=周一 … 7=周日                             |
| `startPeriod` / `endPeriod` | 节次（1–14）                                |
| `location`                  | 地点                                        |
| `classSize`                 | 人数                                        |
| `color`                     | 可选，空则按 `config.js` 中 `COURSE_COLORS` |
| `notes`                     | 备注                                        |

**周次规则**（不在 CSV 中，写在 `js/schedule.js` 的 `inferWeekRule`）：

- `POLI3800` → 第 1–12 周  
- `CS2311` 教书院124 6–7 节 → 单周  
- `CS2311` 理科大楼B120 8–9 节 → 第 1–17 周  
- 其余 → 第 1–17 周

## 四、HCI 理论映射（写报告时可引用）

| 设计决策                     | HCI 理论 / 原则                                               |
| ---------------------------- | ------------------------------------------------------------- |
| 紧凑网格、用餐空行           | 格式塔邻近性；时间隐喻与视觉分组                              |
| 分色 + 字重区分名/地点       | 视觉通道编码；避免仅靠颜色（可访问性）                        |
| 顶栏分区（查询 vs 课表）     | 视觉层次；美学与构成                                          |
| 今日进度条、按节计数         | 认知负荷理论；减少工作记忆负担                                |
| 当前行/列高亮                | 用户心智模型（「现在」应在界面中可见）                        |
| 底部悬浮下一节               | Fitts 定律（大目标、易触达）；Shneiderman「减少短期记忆负担」 |
| 点击跳转详情页（非页内展开） | Hick 定律（渐进披露，避免网格混乱）                           |
| 周次纵向列表选择             | 自然映射（时间顺序）；Fitts（全宽行）；滚轮/Picker 模式       |
| 周次 ‹ › / 左右滑            | 顺序任务模式；Power Law of Practice                           |
| 低保真→高保真 Web 原型       | HCD 流程；原型设计方法                                        |
| 用户访谈 / 可用性测试        | 评估方法；Peer evaluation                                     |

**建议贯穿全文的单一设计原则：**  
「降低获取当前与下一节课信息的认知负荷与交互步数。」

### 用户访谈参考问题

1. 你多久看一次课表？最常完成的任务是什么？（找下一节 / 看整周 / 查地点？）  
2. 现有课表最让你困惑的地方？  
3. 你是否曾认错课程颜色或找不到「现在上到哪了」？  
4. 进度条 / 下一节悬浮栏对你是否有用？  
5. 周次切换你更习惯列表选还是逐周翻？  

### 演示建议流程

1. 打开主页 → 指出顶栏、紧凑网格、分色  
2. 切换周次 → 单周课消失（如第 2 周数据可视化理论课）  
3. 指出今日高亮 + 进度条 + 底部下一节  
4. 点击课程 → 详情页  
5. 说明：数据为 CSV 模拟，未接官方 API（属刻意范围限定）
